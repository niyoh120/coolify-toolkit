# Coolify Toolkit

Homelab 伴侣服务：集中管理 Coolify 中第三方容器镜像的更新。从 Coolify 自动发现资源，追踪指定 tag 的上游内容变化，按资源策略（忽略 / 通知 / 自动更新）执行，并以 **digest 固定** 保证部署目标的确定性对比。

## 核心模型

- **追踪来源（source）**：`registry/repository:tag`，例如 `docker.io/jellyfin/jellyfin:latest`。固定摘要后继续保留，作为持续观察通道。
- **配置摘要（configured digest）**：最近写入 Coolify 的部署目标。首次“更新并固定摘要”会把 tag 固定为当时的顶层 index/manifest 摘要。
- **候选更新**：追踪 tag 的远端摘要 ≠ 配置摘要（含上游回退）。发现策略为“同 tag 内容变化”；跨 tag 升级（如 1.x→2.x）不在首期范围。
- **成功证据**：仅当可关联 Coolify deployment 完成记录时推进（Application）。Compose 子容器首期只有 queued 证据，提交后默认等待约 60 秒做一次运行状态检查（running 即推定成功，来源记录为“运行观察自动确认”）；也可在服务列表或历史中提前「确认更新完成」人工确认。

## 快速开始（开发）

```bash
mise install                # Node 24.19.0
npm ci
cp .env.example .env        # 填入 COOLIFY_BASE_URL / COOLIFY_API_KEY
npm run dev                 # Vite :5173 (代理 /api) + API :8080
npm run check               # typecheck + lint + test + build
```

## 生产部署

见 `compose.yaml` 与 `.env.example`。要点：

1. **鉴权由 Traefik 承担**：UI 与 `/api/*` 共用同一路由，必须挂认证中间件；容器不发布宿主端口。
2. **数据卷**：`/data`（SQLite WAL + 单实例锁）。升级前建议停止容器并备份数据目录（含 `-wal`/`-shm`）。
3. **凭据只在服务端**：`COOLIFY_API_KEY`、`REGISTRY_CREDENTIALS_FILE`、Apprise 配置全部不进前端构建。
4. 首次启动自动执行迁移；迁移失败会拒绝启动。

## 策略与安全默认值

- 新发现资源默认 **忽略**：不检查、不通知、不建任务（追踪 tag 与历史保留）。
- **首次初始化**：任何一次检查（定时扫描或手动「检查更新」）发现资源未初始化时，自动创建 initial_pin 任务，把追踪 tag 固定为当前上游摘要并部署；对所有非忽略策略生效，守卫与自动更新一致（全局暂停、资源停止、被阻塞、同目标在途/失败任务时跳过，留在未初始化态下轮重试）。
- **通知**：检查上游并去重通知；初始化自动执行，初始化后的候选更新始终需要人工预览确认。
- **手动**：候选更新不发通知、全由人工触发；首次初始化仍随检查自动执行。
- **自动更新**：显式启用后，候选出现即建任务（仅定时扫描；手动检查只通知不建任务）；全局暂停、资源停止、被阻塞（外部修改 / 平台缺失 / 上次失败 / 等待自动检查）时自动跳过。

## 资源页与服务分组

- 资源页分「应用」「服务」两个 Tab：`#/resources` 默认应用 Tab，`#/resources?tab=services` 为服务 Tab（非法值回落应用；刷新与前进/后退保持状态）。两个 Tab 统一三档筛选：**未排除**（默认，含待同步确认与镜像问题项）、**受管**（已分类、未排除、无镜像问题且策略为通知/手动/自动）、**已排除**（只读排查）。
- 服务 Tab 按 Compose 服务分组展示：组头显示服务名链接、父级运行状态、服务器/项目与子容器摘要（总数、有更新、待配置/受阻、已排除、待同步），默认展开，并提供折叠/展开全部切换（显示模式，与筛选、翻页无关），按组分页；同名服务保持独立。确认排除的父服务整组默认隐藏，直链详情仍可达；确认排除的子容器默认隐藏，可在排除视图或详情开关中查看。
- 子容器归属其父服务；父服务已从当前列表消失的子容器进入独立异常组，展示已存父名并提供父详情入口。
- 服务详情聚合该服务的全部 active 子容器，提供 **整组检查**、**整组提交更新**、**批量策略**：范围固定为当前 active 快照，确认弹窗列出实际受影响资源与跳过原因。
- 整组更新按子容器逐项建任务（沿用单资源路径）：HTTP 202 表示任务已提交；结果汇总为「已提交 / 跳过 / 失败」。同服务前一个任务在等待自动检查时，后续任务排队。
- **确认更新完成**：服务 Tab 子容器行操作列提供单项「确认更新完成」，立即记录人工确认并解除等待；勾选子容器后可用「批量确认更新完成」，范围是弹窗时冻结的 job+摘要快照，逐项反馈已确认/跳过/失败。批量过程中自动检查先完成或状态变化的项按“状态已变化”跳过，新建任务保持在范围外。
- 列表批量操作的范围是当前页筛选后的选择集；与服务详情的整组范围相互独立，文案明确区分。
- 子容器平台继承父服务节点；节点派生/历史为空的平台在每次完整同步时自动回填自愈（compose 与手动设置的平台保持原值）。

## 管理状态（管理分类与只读边界）

每条资源有明确的管理状态，决定展示归属与操作边界：

- **待同步确认**：历史记录尚未经现行同步规则分类（旧库升级后未同步前）。默认可见、配置只读、新管理动作（策略修改、检查、预览、更新、重试、自定义 cron）暂停；已提交部署的任务保持排队，待同步完成后重新判定资格。完成一次「重新同步」后自动确认。
- **已排除**：自身或父服务命中 `EXCLUDED_RESOURCE_UUIDS` 配置名单。默认列表隐藏（排除视图可查、详情直链可达），配置只读；调整配置并重启、同步后解除。
- **镜像异常**：同步时镜像引用无法解析为受支持的更新目标 —— `暂不支持的镜像仓库：gcr.io`、`镜像变量未解析`、`镜像信息缺失`、`镜像引用无效`。资源保持可见、配置只读，核对 Coolify 实际镜像配置并同步后自动清除。
- 配置排除与镜像问题独立记录：同一资源可同时命中名单且镜像异常，详情页同时解释两种原因。

## 已知边界（首期）

- **回滚功能整体排除**：更新失败时保留当前目标配置、暂停自动更新并通知；处理在 Coolify 完成，toolkit 提供同目标重试与重新同步。
- **Compose 完成证据**：Coolify 4.3.23 子容器 start 仅返回 queued，无 deployment UUID 可关联；提交约 60 秒（受 5 秒轮询与负载影响）后做一次运行观察检查：容器主状态为 running 且子容器 image 与 raw compose 目标节点均等于候选引用即推定成功。等待期间可在列表人工确认；检查失败/漂移则进入失败/冲突终态并暂停该资源。运行观察可能把仍 running 的旧容器推定为成功（静默失败边界），来源与日志会明确标注。
- **Compose 作用范围**：仅自动修改可唯一定位的字面量 `image:`；变量插值、共享 alias、Swarm 等显示受限并拒绝。
- **Registry 范围**：Docker Hub / GHCR / LSCR（匿名或 `REGISTRY_CREDENTIALS_FILE` 提供的只读凭据）；其他 registry 明确报“不支持”。
- **平台**：优先 compose `platform:`，否则节点架构（Coolify sentinel 上报，经 `/resources` 获取）；未上报时待配置，可在资源详情页手动设置。镜像检查默认每天 0 点，可在资源详情页覆盖 cron。
- SDK 无响应体硬上限 / 总时长中止，依赖受信 host 白名单 + 容器内存限制；SDK 内部重试固定为 0，重试由任务层统一调度（尊重 Retry-After）。

## 测试

`npm test` 全部离线可复现：本地 registry fixture（原始字节摘要、多架构、显式平台、鉴权流、错误分类）、Coolify 客户端契约、库存同步（外部修改/移除保护、子容器平台回填与自愈）、检查器（策略/去重/阻塞/明确原因）、执行器（A→B 固定、失败保留证据、冲突、unknown submit、崩溃恢复、Compose 兄弟保护、延迟单次自动检查与人工确认竞态）、通知 outbox（去重/退避/暂停/恢复）、API 公共行为（校验/同源/预览令牌/parent 过滤/待确认 DTO）、资源页视图模型（分组/过滤/分页/选择/outcome 汇总/确认快照）。回滚无专用测试（功能已排除）。
