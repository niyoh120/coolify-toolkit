# 响应式布局回归验证

覆盖窗口变窄、窗口高度降低与浏览器放大三类场景下的前端布局验收：内容溢出、控件挤压、操作不可达。
范围：概览、资源应用列表、资源服务列表（含展开组）、应用/子容器详情、服务详情、更新历史、通知、设置，以及共享导航、分页、表头工具栏、反馈和确认弹窗。

## 运行方式

前置条件（无新增 npm 依赖）：

- agent-browser CLI 在 PATH 中（`agent-browser --help` 可执行），且已安装 Chromium（`agent-browser install`）。
- Node >= 24。
- 自动化浏览器被限制在 `127.0.0.1` / `localhost`（脚本注入 `AGENT_BROWSER_ALLOWED_DOMAINS`）。

```bash
npm run test:responsive            # = npm run build:web + node scripts/verify-responsive.mjs
node scripts/verify-responsive.mjs --shots /some/dir   # 自定义产物目录
```

退出码：`0` 全部断言通过；`1` 存在断言失败；`2` 环境阻塞（CLI/浏览器/fixture 不可用）。
产物（截图 + `results.json`）默认写入 `os.tmpdir()/coolify-responsive-<时间戳>`。

fixture：`tests/fixtures/responsive-ui.mjs`，纯 Node 内存实现，只绑定 `127.0.0.1` 随机端口；
静态文件仅允许 `dist/web` 下的安全路径；未实现的 `/api/*` 返回显式错误并计入 `unknownHits`（脚本断言为空）。
数据为虚构长名称、完整 sha256、长域名/错误/时区、超过一页的应用/历史/通知，以及 8 个超长子容器的服务组。

## 三组回归场景（scripts/verify-responsive.mjs）

**A. 全路由与断点重排**
- 8 个页面 × 宽度 320/375/720/768/1024/1440（高 800），断点相邻 639/640/767/768/1023/1024。
- 断言：`document` 与 `main` 横向溢出 ≤ 1px（仅显式 `[data-allowed-scroll]` 表格/正文滚动区允许溢出）；导航四项、「重新同步」、「全局已暂停」徽标在所有宽度可见；搜索/分段筛选/分页/设置输入位于可达容器内。
- 状态保留：宽度 1024 → 320 切换后搜索词、服务器筛选、勾选保持。

**B. 密集表格与完整数据可达性**
- 应用/历史/通知超过一页；服务列表展开两个组，各自拥有独立滚动 region。
- 断言：滚动只发生在目标表格 region 内；「向右滚动」按钮推进 `scrollLeft` 到右边界，边界处按钮禁用状态翻转；横滚后粘性表头与区域对齐；末列操作按钮单行可读且可点击产生业务反馈；短内容行高 ≤ 96px；复制值与展示字符串一致（History 部署 uuid）；翻页可用。
- 通知标题/错误、历史完整错误通过原生 `<details data-full-text>` 展开，完整文本可读。
- 窗口 320 → 2000 实时变宽后，溢出提示与滚动按钮同步隐藏（ResizeObserver 契约）。

**C. 低高度弹窗、长文案与确认操作**
- 320×568、568×320、720×400 下打开应用批量确认（全选 100/页，含超长资源名）与服务整组更新确认（8 个超长子容器名）。
- 断言：弹窗边界受视口约束；`[data-modal-body]` 正文可滚动；标题/取消/确认可见；打开时焦点移入弹窗，Tab 后焦点元素可见；Escape/取消关闭；确认执行走通并出现业务反馈。

## 浏览器缩放（125% / 150% / 200%）手动验收

CDP 无法真实驱动浏览器缩放；纯 DPR 调整与 CSS zoom 不构成等价证据。自动化已覆盖缩放后的等效 CSS 宽度（例如 1280px 窗口 150% 缩放 ≈ 853px CSS，落在 768–1024 断点档；1440px 窗口 125% ≈ 1152px，落在 1024–1440 档），断点相邻检查（639/640、767/768、1023/1024）即为这些档位的边界。真实缩放请手动复核：

1. Chrome 打开任意 toolkit 页面（本地 dev 或部署实例）。
2. `Ctrl/Cmd + +` 依次调到 125% / 150% / 200%，记录 DevTools Console 的 `innerWidth + 'x' + innerHeight`。
3. 检查：无页面级横向滚动条；表格出现「左右滚动」提示与按钮；低高度窗口（如缩放后余高不足）弹窗正文内滚、确认按钮可达。
4. 记录窗口像素与 `innerWidth/innerHeight` 于本文档下方或审计工单。

最近一次手动复核：待人工执行（自动化环境无法产生真实浏览器缩放）。

## 已知边界与剩余风险

- 自动化基线为 Chromium（agent-browser CDP）；Firefox/Safari 未执行，`ResizeObserver`/`sticky`/`dvh` 行为差异风险保留。
- `--table-max-height` 使用 `60vh` 并在支持 `dvh` 的浏览器升级为 `60dvh`；旧浏览器回退到 vh，低高度窗口下可能有地址栏伸缩引起的轻微高度跳动。
- 表格最大高度为视口 60%：超长列表在表格内部纵向滚动（粘性表头对齐），页面级滚动保留。
- 通知标题默认完整折行显示（保留紧凑性由列宽约束）；若未来标题过长影响扫描效率，可再引入折行上限。
- 行高上限 96px 针对 fixture 的短内容行；长内容（长名+徽标换行）允许更高，属完整信息展示的正常代价。
